# Ползване без регистрация (гост)

Цел: човек отваря приложението и директно попълва данните си (пол, възраст…), натиска „Създай моя план“ и вижда плана — без имейл и парола. Вход/регистрация се предлага чак накрая, с Google.

Подход: **анонимен акаунт в Supabase**. Гостът е нормален потребител за базата (същите таблици и RLS). При вход с Google същият акаунт става постоянен (`linkIdentity`) — нищо не се прехвърля и не се губи.

> Firebase не е нужен: Supabase Auth поддържа Google вход директно.

## Решения (обсъдени)

- [x] Гостът може всичко освен eBag: план, списък за пазаруване, рецепти, отметки.
- [x] Регистрацията е с бутон „Продължи с Google“ (без имейл/парола за новите хора; без Facebook).
- [x] Гост-акаунтите се трият автоматично след **3 дни без активност**.
- [x] Защита от злоупотреба: лимитът на Supabase (30 гост-акаунта на час от IP); captcha само ако видим злоупотреба.
- [x] Първият екран е директно въпросникът (пол, възраст…); въпросът за вход е накрая.

## 1. Настройки на Supabase

- [x] `supabase/config.toml` (локално): анонимен вход, ръчно свързване, redirect URL-и за localhost, блок за Google (изключен локално, докато няма ключове в `supabase/.env`).
- [x] Dashboard (production + тестовия проект) → Authentication → Sign In / Providers: включи **Allow anonymous sign-ins** и **Allow manual linking**.
- [x] Google: OAuth клиент в Google Cloud Console (екран за съгласие, redirect URL към Supabase), Client ID/Secret в Supabase.
- [x] ~~Facebook~~ — отпада (решение 2026-11-26: само Google).
- [x] Dashboard → Authentication → URL Configuration: Site URL = production адресът; Redirect URLs: `https://<домейн>/**`, `http://localhost:3000/**` (и Vercel preview адресите, ако ще тестваш там).

## 2. Въпросникът без вход

- [x] Middleware: `/onboarding` и `/install` са достъпни без сесия; нелогнат потребител на `/` отива на `/onboarding`. По-дълбоки страници (`/plan` и т.н.) без сесия → `/login`. Гост може да отвори `/login`.
- [x] Въпросникът пази отговорите само в браузъра, докато се попълва — гост-акаунт **не** се създава при отваряне на страницата (иначе ботове и случайни посещения правят празни акаунти).
- [x] На последната стъпка („Създай моя план“): ако няма сесия → `signInAnonymously()` → запис на профила → създаване на плана → отваряне на `/plan`. Грешка 429 (лимитът) има отделен текст.
- [x] Бутонът „Изход“ на първата стъпка изчезва за нелогнати; вместо него линк „Имам акаунт — вход“.
- [x] Текстът за съгласие: за гости пише, че данните се пазят 3 дни и после се изтриват.
- [x] E2E тест `e2e/guest.spec.ts` (иска включен анонимен вход в тестовия Supabase проект).

## 3. Покана за регистрация

- [x] Карта на екрана с плана за гости: „Запази плана си“ + „Продължи с Google“; пише, че без вход планът изчезва след 3 дни (`components/SaveAccount.tsx`).
- [x] eBag екранът за гости: вместо „Свържи eBag“ — „Влез, за да изпратиш продуктите в eBag“. `/api/ebag/connect` връща гостите обратно (и на сървъра, не само в интерфейса).
- [x] Бутон „Продължи с Google“ → `linkIdentity` за гост (акаунтът става постоянен, планът остава).
- [x] Ако този Google акаунт вече съществува (`identity_already_exists`): вход в съществуващия акаунт; профилът и последният план на госта се копират, ако акаунтът няма профил, иначе остават старите данни. Гостът се изтрива. ID-то на госта минава през криптирана бисквитка (`lib/auth/guestMerge.ts`).
- [x] Callback route `/auth/callback` — разменя кода за сесия и връща към страницата, от която е тръгнал, с „Готово — планът ти е запазен“ или грешка.
- [ ] Ръчна проверка с истински Google акаунт (нов акаунт и вече съществуващ) — не може да се автоматизира без Google.

## 4. Входният екран

- [x] `/login` вече не е начален екран (middleware праща новите хора на въпросите); остава за „Имам акаунт“.
- [x] Отгоре: „Продължи с Google“. Отдолу, след „или с имейл и парола“: старата форма за вход/регистрация. Най-долу: „Нямам акаунт — започни без регистрация“ → въпросите.
- [x] Логнат потребител (нормален) на `/login` → към `/` (→ плана). Гост на `/login` може да влезе в друг акаунт.
- [x] Гост, който влиза тук, запазва плана си: Google се свързва към него (както в раздел 3); вход или регистрация с имейл също пренасят данните му (`app/login/actions.ts`).

## 5. Изтриване на гост-акаунтите

- [x] Ежедневна задача в базата (pg_cron, 03:17 UTC): `public.delete_stale_guests()` трие анонимните потребители без активност повече от 3 дни. Активност = най-късното от създаване, последен вход и последно опресняване на сесията (отворено приложение я опреснява всеки час). Миграция `supabase/migrations/20261126000000_guest_cleanup.sql`.
- [x] `on delete cascade` чисти профила, плановете и отметките; обратната връзка остава с `user_id = null`. Акаунтите с Google или имейл никога не се пипат.
- [x] Броят изтрити се пише в Supabase → Logs → Postgres (`delete_stale_guests: deleted N guest(s)`); всяко пускане е и в `cron.job_run_details`.
- [ ] Приложи миграцията в production: `npx supabase db push` (README → Migrations). Тестовата база я получава автоматично от CI.

## 6. Разлики гост / регистриран в кода

- [x] `isGuest(user)` в `lib/auth/guest.ts` за сървъра и клиента.
- [x] `/api/ebag/*`: гост получава 403 `guest` с текст „Влез с Google, за да свържеш eBag“; `/api/ebag/connect` го връща на `/ebag`.
- [x] Профил за гост: вместо имейл — „Без вход · пазим данните 3 дни“ и картата „Продължи с Google“; няма „Изход“ (гост, който излезе, губи данните си завинаги); „Изтрий данните ми“ остава. „Изход“ е скрит и на екрана с целите.
- [x] Лимит на `/api/plan` за гости: до 10 плана за 24 часа (429 `too_many`). Акаунтите нямат лимит.

## 7. Тестове

- [x] E2E: отваряне без вход → въпросник → план, без нито един имейл (`e2e/guest.spec.ts`).
- [x] Гост → „Продължи с Google“: покрито с unit тестове на `/auth/callback` и прехвърлянето на данни. E2E с истински Google не може (Google не пуска роботи); остава ръчната проверка от раздел 3.
- [x] RLS тестове (`test/rls/rls.test.ts`): гост вижда само своите данни; само service role може да пуска изтриването; изтриването маха неактивните гости с данните им и никога акаунт.
- [x] Unit тестове: лимитът от 10 плана, 403 за eBag, текстове на двата езика (тестът за преводите).
- [ ] RLS тестовете минават в CI (нужни: миграцията и включен анонимен вход в тестовия проект).

## Решения по отворените въпроси (2026-11-26)

- Без Facebook вход — само Google.
- Съществуващите акаунти с имейл и парола остават завинаги; не ги подканяме към Google.
- 3 дни е достатъчно — остава така.
